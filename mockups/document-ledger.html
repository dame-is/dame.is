The ledger, five ways

One row of columns on desktop; the question is what happens when the column narrows. Each version below is shown at the reading measure and at 340px, and the phone rig reports the band's measured height so the vertical cost is a number rather than a feeling. Both rigs are the same CSS — the layouts switch on a container query, not the viewport, so the band responds to the document column rather than the window.

Specimen palette
L0

Where we left off

Three columns on desktop, stacking to three label/value rows on a phone. The desktop row is right; the stack is what costs the height.

L1

Fold the elapsed in

Keep three columns wide. Narrow, the elapsed column doesn't stack — it folds into the date as a clause, so the band goes to two columns and stays two lines tall. Same facts, half the height.

Why it works
Nothing is lost and nothing moves to a new line — the two facts that belong together (when, how long ago) end up in one cell, which is where they read best anyway.
Cost
Two renderings of the elapsed value in the markup, one hidden at each width. Cheapest fix to the height problem.
L2

Inline labels

Move each label onto its value's line. Every cell is one line at any width, so the whole band is one line — the shortest version that still labels anything. Narrow, the elapsed cell drops.

Why it works
One line, three cells, right edge held. It's the closest thing to today's dateline that's still a ledger — a segmented sentence rather than a table.
Cost
"1 year ago" disappears on phones. Defensible (the date is right there) but it is a real loss — relative time is what makes an old post read as old.
L3

Table head

A real two-line table: header row, value row, columns aligned at both widths. Nothing is dropped or folded — the values abbreviate instead. The most ledger-like of the set.

Why it works
The layout never changes shape, so the header looks the same on every device — and the columns stay true columns, which is the thing you liked about the ledger.
Cost
Abbreviations need real logic: "Jun 27, 2025" and "1 yr" are format decisions, not CSS. Two lines rather than one, and the narrow columns get tight with a longer elapsed value ("11 months").
L4

Hairline run

Drop the labels entirely except the one that needs it. Values separated by hairlines, day count flush right. Identical structure at both widths — there's nothing left to reflow.

Why it works
The lightest band of the five and the only one that's genuinely width-proof. It also echoes the segmented strip above it exactly, which is what makes the two rows read as one system.
Cost
Unlabelled. A date and an elapsed phrase explain themselves; a bare number wouldn't, which is why "Day" survives — and that asymmetry is either a nice detail or an itch, depending on you.
L5

Weighted

Two cells, not three: everything about the date on the left, the day count alone on the right at display size. The band stays two lines but only one of them is doing the talking.

Why it works
The only version where the day count is sized like it matters. Two cells survive a narrow column far better than three, so nothing has to be hidden or abbreviated.
Cost
It's a statement. On a document where the date is the interesting fact and the day number is incidental, the emphasis is backwards.

Where I'd land

  • L1 if you want the ledger you already liked, just shorter on a phone. It's the same design; the only new idea is that the elapsed value folds into the date instead of claiming a row of its own.
  • L4 if the band should get out of the way. One line at every width, no breakpoint, and it rhymes with the segmented strip directly above it — the two bars become one instrument. This is the one I'd ship.
  • L3 if you want it to look the same on every device. The cost is real formatting work: short-form date and elapsed strings, not just CSS.
  • Whichever wins, keep font-variant-numeric: tabular-nums on the day count and put the breakpoint on a container query rather than the viewport — the document column is capped at 65ch, so it narrows on a wide window too (side-by-side windows, the print view), and a viewport query would miss that.
  • The elapsed value is the one that changes length wildly — "today", "3 days ago", "11 months ago", "1 year ago". Test the band against relativeDay()'s longest output, not this one. 
/* The container query, wherever it lands */
.document-meta { container-type: inline-size; }   /* or on .page */

@container (max-width: 26rem) {
  /* L1: the elapsed column folds into the date */
  .document-meta .col-elapsed { display: none; }
  .document-meta .fold        { display: inline; }
